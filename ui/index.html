    System Manual

    Quick guide for daily operation and support

    How to Use the System

    1. Sign in on the local gate page (no device account check).
    2. Dashboard cards show live RTC time, next bell, and mode from GET /api/telemetry.
    3. Edit the bell table — every save does GET → modify → POST /api/schedule with keys id, subject, days[], startTime, endTime, chimeStart, chimeEnd.
    4. Open Attendance for live probe-request detections (GET /api/attendance).
    5. Use Backup to download schedule.json.

    Firmware API Reference (v2.2.0)

    • GET /api/telemetry → {time,status,ssid,ap_ssid,attendance,sniffer,schedule_count,ntp_ok,last_ntp}
    • GET /api/schedule → {schedules:[{id,subject,days,startTime,endTime,chimeStart,chimeEnd}]}
    • POST /api/schedule (JSON) → {status:"ok"}
    • GET /api/attendance → CSV Timestamp,MAC_Address,RSSI,Status
    • GET /api/attendance/status → {active:bool}
    • GET /ring?file=name.wav → queues chime → {status:"ok"} (404 if the WAV is not on SD; legacy .mp3 names auto-map to .wav)
    • GET /api/audio/list → {files:[{name,size}]}
    • POST /api/audio/upload (multipart .wav ≤300KB) → {status:"ok",name,size}
    • POST /api/time/sync → NTP sync RTC (needs STA online) → {status:"ok",time}
    • GET /api/activity?limit=N → {events:[{t,ev}],count} (newest first)
    • GET /api/config → {ap_ssid,sta_ssid,sta_pass}
    • POST /api/config (JSON) → {status:"ok"}
    • POST /handleLogin (urlencoded) → {status:"ok"} + session cookie
    • GET /logout → expires session, redirects to /
    • GET /test → connectivity check

    Frequently Asked Questions

    Can I change the bell audio?

    Yes — upload a 16-bit mono .wav (≤300KB) via System Controls, then pick its file name in the schedule form (stored as /audio/<name>). No SD card removal needed.

    Why do my schedules not ring on some days?

    Check the day checkboxes — the firmware only fires entries whose days[] bitmask matches the RTC weekday.
